## Problem Statement
Extract every recommendation, its strength and its certainty/level of evidence
from full guideline PDFs with a local LLM (single RTX 3090). Produce:
1. a Fanaroff-style (JAMA 2019) analysis of the last 10 years of guidelines;
2. a living overview: adding one guideline triggers extraction of that
   guideline only, then an automatic refresh of statistics, figures and dashboard.

## What Makes This Cool
- Prior LOE meta-research (cardiology, ESMO oncology) is manual and one-off.
  This one is living, local, and extends across specialties.
- Once data exists, "discordance" queries are cheap: strong recommendations
  resting on low/very-low certainty (a GRADE-adherence audit), and ESICM vs
  SCCM disagreement on the same question.
- In GRADE guidelines the grade is printed, not inferred. The LLM transcribes;
  the hard part is deciding what counts as a recommendation.

## Constraints
- Local model only (≤24 GB VRAM, Ollama). Python 3.9 in main env.
- Existing code (`extraction/`, `evaluation/`) is exploratory and may
  perform worse than reported: treat as a replaceable strategy, not a core.
- Reported scores were tuned on the same 15 labelled guidelines (ML filter,
  adaptive threshold, few-shot pool). FT v3 (F1 0.808) was trained on those
  guidelines, so its score is in-sample.
- `extraction/datasets.py:164` loads only the first `.xlsx` in the ICU dir.

## Premises (agreed)
1. Unit = one recommendation. Headline = % high/moderate certainty and % strong,
   by society and year.
2. Ungraded statements (best-practice statement, no recommendation, consensus)
   are extracted as a separate category. The denominator rule is explicit and reported.
3. All editions stored. The "current map" uses the latest edition per topic;
   trends use all editions. A new guideline can supersede an older one.
4. (revised) Guideline = atomic ingest unit. Each run stores model, prompt hash,
   git SHA and config. Between snapshots, adds extract only the new guideline.
   A published snapshot re-extracts everything with one frozen version.
   Stats are always a full recompute.
5. Grades are harmonized to strength {strong, weak/conditional, against-strong,
   against-weak, ungraded} × certainty {high, moderate, low, very low, NA}.
   The raw grade is always stored.

## Recommended Approach: B — layered package
Each layer calls only the layer directly below it.

```
 CLI  evident add <pdf> | snapshot | publish | validate | status
      (`add` = IngestService then PublishService, chained by the CLI; DOI input
       deferred until open question 1 is resolved)
  │
  ▼
 services ──────────────────────────────────────────────────────────────
  IngestService     add one guideline: register → extract → harmonize → store,
                    always with the current snapshot's frozen ExtractorVersion
  SnapshotService   freeze ExtractorVersion, re-extract all, tag snapshot
  PublishService    analytics → figures/tables + static dashboard
  ValidateService   run labelled subset vs GT for a given ExtractorVersion
  │
  ├── corpus         manifest (doi, society, year, topic_id, supersedes),
  │                  PDF registry, edition/supersession rules
  ├── extraction     ExtractionStrategy interface; LegacyLLMStrategy wraps
  │                  current extraction/ best config; ExtractorVersion =
  │                  {strategy, model, prompt_hash, git_sha, config}
  ├── harmonization  per-scheme mapping raw → common scale (+ ungraded)
  ├── analytics      headline stats, trends, discordance, CIs (pure functions
  │                  over repository reads)
  └── store          repository API over SQLite; migrations
                     tables: guideline, extractor_version, extraction_run,
                             recommendation, snapshot
```

Package root: `evident/` (new). `evident/extraction/` holds the strategy
interface; `LegacyLLMStrategy` imports the existing top-level `extraction/`
package unchanged.

Domain module dependencies (services orchestrate; modules never call services):
```
 corpus        → store
 extraction    → (legacy extraction/, Ollama)   no store access
 harmonization → (pure; scheme tables)          no store access
 analytics     → store (read-only)
 services      → corpus, extraction, harmonization, analytics, store
```

Run and version rules:
- Active run per guideline = latest successful run whose ExtractorVersion is
  the current snapshot's. Stats read active runs only.
- A new ExtractorVersion enters only via `snapshot`. `add` never changes version,
  so the dashboard is never mixed-version.
- Duplicate ingest (same DOI or PDF SHA-256): no-op with a message; `--force`
  creates a new run that replaces the active run.

Denominator rule (premise 2):
- Total count = graded + ungraded.
- % by certainty and % strong are computed over graded recommendations only.
- The ungraded share is reported as its own figure.

Validation metrics:
- Matching is as in `evaluation/` (BioLORD + Hungarian); P/R/F1 per guideline.
- Grade accuracy is scored on harmonized strength and certainty separately;
  raw-grade accuracy is reported too.
- 95% CIs use a guideline-cluster bootstrap, since recommendations cluster within guidelines.

Ingest flow (incremental):
```
 PDF + manifest row ─▶ corpus.register ─▶ extraction.run(version)
   ─▶ harmonization.map ─▶ store.save(run)      [IngestService]
   ─▶ analytics (full recompute) ─▶ figures + dashboard   [PublishService, chained by CLI]
```

Failure handling (no silent failures):
- Zero recommendations extracted → run stored as `FAILED_EMPTY` and excluded
  from stats; `status` lists it.
- Unmappable raw grade → recommendation stored with `harmonized=NULL` and a
  `unmapped` count shown on the dashboard.
- Scheme not detected → ingest refuses with a named error. The user sets the
  scheme in the manifest.
- Partial extraction (low recall) → no automatic detection. `status` flags
  guidelines whose recommendation count or ungraded share is an outlier
  versus the society median. This is a known blind spot, bounded by `validate`.

## Success Criteria
- `evident add <pdf>` on a new guideline updates the DB, figures and dashboard
  in one command, without re-reading other guidelines.
- `evident snapshot` reproduces every published number from one
  ExtractorVersion.
- `evident validate` reports P/R/F1 and grade/certainty accuracy on the
  labelled ACP + ESICM subset, with 95% CIs, for any ExtractorVersion.
- The MVP figures replicate Fanaroff's core tables for ESICM/SCCM/ACP:
  % by certainty, % strong, trends by year, by society.

## Eng Review Decisions (2026-10-01, /plan-eng-review)
Each item was approved individually.

- **Scope (slim layered, ~8 files):**
  - `evident/cli.py`
  - `evident/pipeline.py`, with the plain functions `add`, `snapshot`, `publish`, `validate`, `status`; no service classes
  - `evident/{store,corpus,extraction,harmonization,analytics,publishing}.py`
  - The strategy "interface" is a function signature until a second strategy exists.
- **1A Ungraded category:**
  - The prompt and `response_parser` emit `category` ∈ {graded, best_practice, no_recommendation}.
  - Prompt v1 is compared against v0 through `validate` before it becomes ExtractorVersion v1.
- **1B validate scores stored runs:**
  - Stored recommendations of labelled guidelines (DOI join to `load_acp_datasets` / `load_icu_datasets`) are scored with `evaluation/` matching and metrics.
  - No re-extraction.
- **1C Snapshot state machine:**
  ```
  building ──all guidelines ok/excluded──▶ complete ──validate gate pass──▶ published
     ▲  │ crash: per-guideline commits kept
     └──┘ snapshot --resume skips done guidelines
  ```
  - A failed guideline blocks `complete` until it is retried or `--exclude <doi> --reason "<text>"`.
  - `publish` and `add` use only the latest `published` snapshot.
- **1D Page provenance:** each recommendation stores `page` (first page after dedup) and its chunk id.
- **2A ExtractorConfig:**
  - A frozen dataclass in `evident/extraction.py`, with enums for modes.
  - Canonical JSON → SHA-256 → version id; called as `extract_guideline(**cfg.kwargs())`.
  - `run_benchmark.py` is untouched.
- **2B Reproducibility:**
  - ExtractorVersion stores the Ollama model digest; a live mismatch raises `ModelDigestMismatch`.
  - `llm_client` gets an optional `seed` (seed = base + sample index).
- **3A Gate:**
  - `publish` refuses unless `validate` shows F1 and harmonized-grade accuracy ≥ the previous published version − 0.02, or `--accept-regression "<reason>"` is given (the reason is stored).
  - The GT loaders get an opt-in that keeps ungraded rows as `category=ungraded`. The default behaviour is unchanged.
- **4A:** BioLORD and the classifier are loaded once per process and injected via `dedup_model` / `ml_similarity_model`.
- **4B:** `extraction_run` stores `duration_s`, `n_pages`, `n_llm_calls` and `thinking`. `status` shows the snapshot ETA and flags guidelines more than 3× slower than the median.
- **OV1:** `ExtractorConfig.run(pdf)` picks the entrypoint from a mode enum (SINGLE_PASS / SELF_CONSISTENCY / TABLE_FIRST), builds the PromptStrategy itself, and hashes the strategy name and examples.
- **OV2:**
  - Few-shot exclusion uses the DOI→GT-key map, and the draw is seeded.
  - The chosen examples are stored on the run.
  - A test asserts that a target's GT never appears in its own prompt.
- **OV3:**
  - `harmonization` owns direction: from the label, else from the text ("recommends against", "suggests not", …).
  - "insufficient" maps to ungraded.
  - Raw extractor output is stored before normalization. `evaluation/grading.py` is unchanged.
- **OV4 gate:**
  - Compares graded-only F1 and grade accuracy on a fixed GT mode, using a paired guideline-cluster bootstrap. It fails only if the 95% CI of the difference lies entirely below −0.02.
  - Ungraded P/R is reported separately and is not part of the gate. v0 = the legacy config.
  - `validate` hard-fails unless the DOI join matches all 12 labelled guidelines.
- **OV5:** snapshot membership is frozen at start. `complete` re-scans the manifest. `publish` and `status` refuse or flag any manifest guideline without an active run.
- **OV6:** `page` and `chunk_id` are tagged per row before concat. A merge (dedup or SC) keeps the min page across members.
- **OV7:**
  - Reproduction means an exact recompute from stored runs.
  - Raw LLM responses are stored. ExtractorVersion includes the classifier SHA-256 and the embedding model revision.
  - Re-extraction is "close", and `validate` measures how close.
- **OV8:**
  - Strength and certainty are each categorized as {mapped, ungraded, unmapped}.
  - Every caption states the excluded and unmapped counts.
  - SCCM is labelled "accuracy unvalidated".
- **Added to scope:**
  - **Table-first strategy (Docling/Marker)** as the second extraction mode, A/B-tested via `validate`.
  - **FT v3 leave-one-guideline-out re-evaluation** before choosing v1.
